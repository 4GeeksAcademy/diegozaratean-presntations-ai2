Las pruebas automatizadas garantizan que los cambios futuros no rompan la funcionalidad existente:

Verifican que la ruta de FastAPI responda correctamente conectándose a la BD de pruebas.

🧪 Testing en FastAPI con `pytest` y `TestClient`

test_auth.py
Python
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_login_exitoso():
    response = client.post("/login", json={"username": "admin", "password": "123456"})
    assert response.status_code == 200
    assert "access_token" in response.json()

def test_login_password_incorrecto():
    response = client.post("/login", json={"username": "admin", "password": "wrong"})
    assert response.status_code == 401
🚀 Sin servidor real:

TestClient ejecuta las solicitudes HTTP directamente en memoria sin necesidad de levantar uvicorn.

✅ Aserciones `assert`:

Pytest evalúa expresiones Python estándar con assert y reporta diferencias de forma clara.

🧩 El Patrón Arrange - Act - Assert (AAA)

1️⃣
Arrange (Preparar):

Configurar el estado inicial, crear datos de prueba o mockear dependencias externas.

2️⃣
Act (Ejecutar):

Invocar el método o endpoint a probar: response = client.post(...).

3️⃣
Assert (Verificar):

Verificar que la respuesta obtenida coincide exactamente con la respuesta esperada.

🎯 Conceptos Clave que Deben Dominar

🏝️ Aislamiento Total de Pruebas

Cada prueba debe ser independiente y ejecutarse sobre datos limpios. Una prueba nunca debe depender del resultado de otra.

⚙️ Pytest Fixtures

Funciones con @pytest.fixture para inyectar clientes TestClient o semillas de datos repetibles sin duplicar código.

🎯 Probar Casos de Error (Edge Cases)

No probar solo el "happy path". Verificar que la API retorne 400, 401 o 404 cuando reciba entradas inválidas.

🤖 Automatización en CI/CD

Ejecutar pytest automáticamente en GitHub Actions antes de desplegar a producción para evitar regresiones.

Fundamento Teórico
⚡ Principio Fundamental:

💻 Ejemplo Práctico: Pytest Fixtures & Dependency Injection Overrides

Analogías & Código
💡 Analogía 1 (Caso Práctico):

Para jugar al doctor no usas medicinas reales. Usas un estetoscopio de plástico y dulces como si fueran pastillas (Fixtures). Así juegas seguro sin ningún peligro.

💻 Código Técnico del Contrato: 
@pytest.fixture
def client(db_session):
    app.dependency_overrides[get_db] = lambda: db_session
    with TestClient(app) as c:
        yield c
🔍 Aplicación en el Código:

Inyectar dependencias de prueba permite reemplazar la base de datos de desarrollo por una base de datos en memoria para los tests.

✅ Criterio de Producción:

Garantiza que las pruebas se ejecuten sobre una BD aislada sin tocar datos reales.

🧠 Concepto 3: Aislamiento Total y Rollback de Transacciones

Fundamento Teórico
📖 Definición Técnica:

Ejecutar cada test dentro de una transacción que realiza rollback automático al finalizar.

⚙️ Mecanismo e Implementación:

Previene que los datos creados o modificados por un test contaminen el estado inicial del siguiente test.

🛡️ Criterio de Arquitectura Senior:

Evita fallos intermitentes y dependencias ocultas del orden de ejecución en la suite de pruebas.

⚠️ Puntos Trampa (Gotchas) & Criterios Ready for Production

🚨 Gotchas / Errores Comunes de Estudiantes:
🚨 Dependencia del Orden: Tests que pasan individualmente pero fallan al ejecutarse en suite completa por fugas de estado.
🚨 Peticiones HTTP Reales: Olvidar mockear clientes HTTP de terceros (ej: APIs de pagos/email) ejecutando llamadas reales en tests.
🚨 Probar Solo 'Happy Paths': Probar únicamente respuestas 200 u omitir validaciones de errores 400/404/422.
🚨 Base de Datos Contaminada: No limpiar ni hacer rollback a las tablas después de cada test.
✅ Checklist "Listo para Producción":
✅ conftest.py define fixtures reutilizables con scope de función.
✅ app.dependency_overrides garantiza que ningún test toque la base de datos de desarrollo.
✅ Se prueban casos exitosos (2xx) y casos de error esperados (4xx).
✅ Las llamadas a servicios externos están 100% mockeadas (unittest.mock / respx).
✅ La suite de pruebas se ejecuta de forma totalmente autónoma e independiente.
