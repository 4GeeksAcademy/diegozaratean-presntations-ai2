2. Fundamentos RESTful y Operaciones CRUD
</> 4Geeks academy

Mapeo de Verbos HTTP

Interfaz uniforme basada en recursos en plural (/ideas) y acciones HTTP:

GET (/ideas): Obtener todas las ideas de negocio (200 OK).
POST (/ideas): Registrar una nueva idea de negocio (201 Created).
PUT (/ideas/{id}): Reemplazo total de la idea (200 OK).
PATCH (/ideas/{id}): Actualización parcial (ej. validated: true) (200 OK).
DELETE (/ideas/{id}): Eliminación de la idea (200 OK / 204).

Convenciones vs. Anti-patrones

❌ Anti-patrones Comunes

/getIdeas, /createIdea, /updateIdea/1
Usar verbos en la URL duplica la semántica del método HTTP.

✅ Diseño REST Correcto

GET /ideas
POST /ideas
PUT /ideas/1

from pydantic import BaseModel, Field
from typing import Optional

class IdeaBase(BaseModel):
    title: str = Field(..., min_length=1, description="Título de la idea")
    category: str = Field(default="Tech", description="Categoría del negocio")
    validated: bool = Field(default=False, description="Estado de validación")

class IdeaCreate(IdeaBase):
    pass

class IdeaUpdate(BaseModel):
    title: Optional[str] = None
    category: Optional[str] = None
    validated: Optional[bool] = None

class IdeaResponse(IdeaBase):
    id: int

class IdeaCreateSchema(BaseModel):
    title: str
    category: str = "Tech"
    validated: bool = False

class IdeaPatchSchema(BaseModel):
    title: Optional[str] = None
    category: Optional[str] = None
    validated: Optional[bool] = None

class InstructionRequest(BaseModel):
    transcription: str

class InstructionResponse(BaseModel):
    endpoint: str
    method: str
    params: Optional[dict] = None

GET /ideas & POST /ideas

Operaciones iniciales para listar ideas de negocio y registrar nuevas con un ID incremental autogenerado.

🟢 Status 201 Created

El decorador POST declara explícitamente el código HTTP 201.

src/main.py (GET & POST)
Python
@app.get("/ideas", status_code=status.HTTP_200_OK)
def get_ideas():
    return ideas

@app.post("/ideas", status_code=status.HTTP_201_CREATED)
def create_idea(idea_data: IdeaCreateSchema):
    global idea_counter
    new_idea = {
        "id": idea_counter,
        "title": idea_data.title,
        "category": idea_data.category,
        "validated": idea_data.validated
    }
    ideas.append(new_idea)
    idea_counter += 1
    return new_idea
11. Endpoints CRUD: Edición y Borrado (PUT, PATCH, DELETE)
</> 4Geeks academy

Edición & Borrado por ID

Reemplazo total (PUT), actualización parcial (PATCH) y eliminación (DELETE) manejando errores 404 Not Found.

🔴 Manejo de Excepciones 404

Si el idea_id no existe en la lista en memoria, se eleva HTTPException(status_code=404).

src/main.py (PUT, PATCH, DELETE)
Python
@app.put("/ideas/{idea_id}", status_code=status.HTTP_200_OK)
def update_idea(idea_id: int, idea_data: IdeaCreateSchema):
    for index, idea in enumerate(ideas):
        if idea["id"] == idea_id:
            updated_idea = {"id": idea_id, "title": idea_data.title, "category": idea_data.category, "validated": idea_data.validated}
            ideas[index] = updated_idea
            return updated_idea
    raise HTTPException(status_code=404, detail="Idea not found")

@app.patch("/ideas/{idea_id}", status_code=status.HTTP_200_OK)
def patch_idea(idea_id: int, idea_data: IdeaPatchSchema):
    for idea in ideas:
        if idea["id"] == idea_id:
            if idea_data.title is not None: idea["title"] = idea_data.title
            if idea_data.category is not None: idea["category"] = idea_data.category
            if idea_data.validated is not None: idea["validated"] = idea_data.validated
            return idea
    raise HTTPException(status_code=404, detail="Idea not found")

@app.delete("/ideas/{idea_id}", status_code=status.HTTP_200_OK)
def delete_idea(idea_id: int):
    global ideas
    idea_to_delete = next((i for i in ideas if i["id"] == idea_id), None)
    if not idea_to_delete: raise HTTPException(status_code=404, detail="Idea not found")
    ideas = [i for i in ideas if i["id"] != idea_id]
    return {"message": f"Idea {idea_id} deleted successfully"}
12. Endpoint de Instrucciones con LLM (Groq)
</> 4Geeks academy

POST /instruction

Convierte texto de voz a JSON estructurado para el enrutamiento de la API.

⚠️ Regla Clave: Enrutamiento IA

No uses condicionales manuales (como if "add" in text:). El enrutamiento debe ser inferido 100% por el LLM.

src/main.py (Groq Endpoint)
Python
@app.post("/instruction", response_model=InstructionResponse, status_code=status.HTTP_200_OK)
def process_instruction(instruction: InstructionRequest):
    system_prompt = """
You are an API router assistant for a Business Ideas Management application.
Convert the user's natural language voice transcription into a structured JSON action.

Available endpoints:
- GET /ideas -> to list all business ideas. (params: {})
- POST /ideas -> to create a new idea. (params: {"title": "<string>", "category": "<string>", "validated": false})
- PUT /ideas/<idea_id> -> to fully replace an idea. (params: {"title": "<string>", "category": "<string>", "validated": <bool>})
- PATCH /ideas/<idea_id> -> to update an idea title, category or status. (params: {"title": "<string>"} or {"validated": <bool>})
- DELETE /ideas/<idea_id> -> to delete an idea. (params: {})

Rules:
1. Output ONLY a valid JSON object. No explanations.
2. The format MUST be exactly:
{
  "endpoint": "/ideas" or "/ideas/<id>",
  "method": "GET" | "POST" | "PUT" | "PATCH" | "DELETE",
  "params": { ... }
}
"""

    response = groq_client.chat.completions.create(
        model="llama3-8b-8192",
        messages=[
            {"role": "system", "content": system_prompt},
            {"role": "user", "content": instruction.transcription}
        ],
        temperature=0.0,
        response_format={"type": "json_object"}
    )

    result_json = json.loads(response.choices[0].message.content)
    return result_json
