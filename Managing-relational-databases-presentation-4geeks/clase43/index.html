⚡ ORM (SQLModel/SQLAlchemy) & Estrategia Dual Database

FastAPI • SQLite vs PostgreSQL
📌 ¿Qué es un ORM (Object-Relational Mapping)?

Mapea clases de Python (Objetos) directamente a tablas relacionales de la BD. Permite consultar, insertar y actualizar datos mediante métodos orientados a objetos en lugar de cadenas SQL manuales.

🪶 SQLite (Desarrollo & Tests)

Base de datos ligera basada en un archivo local sin servidor daemon. Ideal para prototipado rápido y ejecuciones ultra rápidas de Pytest.

🐘 PostgreSQL (Producción)

Motor relacional de alto rendimiento, concurrente y cliente-servidor para entornos de producción masivos.

💻 Definición de Modelos & Conexión Engine

models.py
Python
from typing import Optional
from sqlmodel import SQLModel, Field, create_engine, Session

# Modelo ORM + Esquema Pydantic Unificado
class User(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    email: str = Field(unique=True, index=True)
    hashed_password: str

# Conexión Dinámica Dual Database vía .env
DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///./dev.db")
engine = create_engine(DATABASE_URL, echo=True)
✨ SQLModel (Pydantic + SQLAlchemy):

Una sola clase define la tabla SQL y valida los JSONs del contrato de la API FastAPI.

🔌 Abstracción de Motor (`create_engine`):

El código Python del backend funciona identicamente en SQLite y PostgreSQL cambiando solo la cadena `DATABASE_URL`.

🏦 El Patrón Session, Engine & Commit/Rollback

Gestor de Transacciones • Conexiones
📌 Explicación Técnica:

El Engine administra el pool de conexiones físicas a la BD. La Session representa la transacción activa: acumula cambios (`session.add()`), los persiste en la BD (`session.commit()`) o revoca operaciones ante errores (`session.rollback()`).

🏦 Ejemplo Feynman (para 5 años):

Es la ventanilla del banco: abres la atención en ventanilla (Session). Le pones los billetes en la bandeja (session.add). El cajero sella el depósito (commit) y se guarda. Si algo falla, te devuelve los billetes y destruye el papel de depósito (rollback).

📁 Archivos donde interviene / se configura:

`app/core/db.py`, dependencias `get_session()` en routers y fixtures de pruebas en `conftest.py`.

📦 Migraciones de Base de Datos con Alembic

Control de Versiones de BD • DDL Automático
📌 Explicación Técnica:

Alembic rastrea los cambios en los modelos Python de SQLModel y genera versiones DDL automáticas (`alembic revision --autogenerate`), permitiendo actualizar (`alembic upgrade head`) o revertir el esquema de producción sin perder datos.

🎮 Ejemplo Feynman (para 5 años):

Son los puntos de guardado (savepoints) en un videojuego. Si modificas el mapa del nivel (agregas columnas a la BD), guardas la partida en una revisión. Si la actualización falla, haces `downgrade` al savepoint anterior sin perder tu personaje.

💻 Comandos de Migración Alembic: 
# Generar script de migración automático
alembic revision --autogenerate -m "add_users_table"
# Aplicar cambios a la base de datos
alembic upgrade head

🔄 Estrategia Dual Database: SQLite vs PostgreSQL

Dev Fast • Prod Robust
📌 Explicación Técnica:

SQLite es ultra ligero e ideal para pruebas rápidas en local sin instalar servicios. PostgreSQL es el motor cliente-servidor para producción. La capa ORM abstrae el SQL para cambiar entre ambos mediante `DATABASE_URL` sin tocar el código.

✈️ Ejemplo Feynman (para 5 años):

Es el simulador de vuelo en tu computadora (SQLite) versus volar el avión comercial real con 200 pasajeros (PostgreSQL). Practicas tus maniobras rápido en el simulador sin gastar combustible real.

📁 Archivos donde interviene / se configura:

Variables de entorno (.env), docker-compose.yml y app/core/config.py.

⚠️ Gotchas Críticos en FastAPI + ORM

❌ Problema N+1 Queries:

Consultar una lista de N elementos e invocar su relación dentro de un bucle ejecuta N+1 consultas HTTP/BD. Usar selectinload().

⚠️ Sesiones No Cerradas:

No usar generadores yield en get_session puede agotar el pool de conexiones a la base de datos.
