⚡ ORM (SQLModel/SQLAlchemy) & Estrategia Dual Database

FastAPI • SQLite vs PostgreSQL
📌 ¿Qué es un ORM (Object-Relational Mapping)?

Mapea clases de Python (Objetos) directamente a tablas relacionales de la BD. Permite consultar, insertar y actualizar datos mediante métodos orientados a objetos en lugar de cadenas SQL manuales.

🪶 SQLite (Desarrollo & Tests)

Base de datos ligera basada en un archivo local sin servidor daemon. Ideal para prototipado rápido y ejecuciones ultra rápidas de Pytest.

🐘 PostgreSQL (Producción)

Motor relacional de alto rendimiento, concurrente y cliente-servidor para entornos de producción masivos.

🌉 Módulo 1: Fundamentos del Puente ORM y Modelado

ORM • Mapeo Objeto-Relacional • SoundWave DB
📌 Concepto:

Un ORM (Object-Relational Mapping) actúa como un traductor entre el código orientado a objetos y las tablas SQL. En lugar de escribir SQL manual, se definen clases (modelos) donde cada clase representa una tabla, cada atributo una columna, y cada instancia un registro.

🗣️ Explicación Feynman:

Imagina que hablas español (código) y tu amigo solo habla japonés (base de datos SQL). Un ORM es un intérprete bilingüe: cuando le dices "crea una canción llamada 'Get Lucky' a 2 dólares", el intérprete traduce eso a orden en japonés (INSERT INTO songs...) sin que tengas que aprenderte todos los kanjis.

class Song(Base):

🛒 Módulo 3: Sesiones (`Session`), Transacciones, Commit & Rollback

Unit of Work • Atomacidad • Commit / Rollback
📌 Concepto:

La Session actúa como espacio de trabajo en memoria (Unit of Work). Prepara cambios con session.add() y los impacta en la BD de forma atómica con session.commit(). Si ocurre un error, session.rollback() revierte todo.

🛒 Explicación Feynman:

Es como el carrito de supermercado. Metes productos (session.add()) pero aún no se paga ni se mueve dinero. En la caja registradora pagas todo junto (session.commit()). Si olvidaste la billetera, vacías el carrito completo sin alterar la tienda (session.rollback()).

SoundWave DB - Flujo de Transacción
Python
with Session(engine) as session:
    # 1. Consultar registro
    cancion = session.query(Song).filter_by(id=101).first()

    # 2. Modificar en memoria
    cancion.price = 1.99

    # 3. Insertar nuevo objeto
    nuevo_artista = Artist(name="Feid", country="Colombia")
    session.add(nuevo_artista)

    # 4. Confirmar transacción atómica
    session.commit()

🔄 Ciclo de Vida de los Datos: Del Código a la Base de Datos

Cómo el ORM gestiona y asegura los cambios en memoria y en disco

Session • Transaction • Commit • Rollback
📝 Sesión (Session)

Tu mesa de trabajo en Python. Rastrea qué objetos creas, modificas o eliminas antes de tocar la base de datos.

🛒 Analogía: El carrito de compras
🛡️ Transacción

La barrera de seguridad de la base de datos. Agrupa todas las operaciones bajo la regla de "todo o nada".

💳 Analogía: Pasar por la caja registradora
✅ Commit

La orden de confirmación. Guarda los cambios de forma permanente y los hace visibles para los demás.

🧾 Analogía: Pagar y recibir el ticket
🚨 Rollback

El botón de pánico. Si ocurre un error, cancela todo y devuelve la base de datos a su estado original sin dejar datos corruptos.

🎒 Analogía: Vaciar el carrito si olvidaste la billetera
👑 Regla de Oro: La Sesión prepara la jugada, la Transacción la protege, el Commit la firma y el Rollback la borra si algo sale mal.

🍽️ Módulo 4: Evaluación, Optimización & Problema N+1

N+1 Query Avoidance • Best Practices • Performance
📌 Concepto:

Evaluación integral del ciclo de vida del ORM, identificando trampas de rendimiento como el Problema N+1 Queries (disparar N consultas secundarias dentro de un bucle en vez de un JOIN único) y validación estricta de tipos.

🍱 Explicación Feynman:

Imagina pedirle a un mesero 10 platos de comida, pero en vez de traerlos en una sola bandeja grande, hace 10 viajes individuales a la cocina trayendo un plato cada vez. Usar bien el ORM es enseñarle al mesero a traer la bandeja completa de una sola vez.

⚡ Reglas de Oro de Rendimiento ORM:
  • Carga Ansiosa (Eager Loading): Usar joinedload() o selectinload() para traer relaciones en una sola consulta SQL.
  • Gestión de Sesión: Encapsular con with Session(engine) as session: para evitar fugas de conexiones.
  • Filtrado en BD: Usar session.query().filter() en lugar de traer miles de registros a Python para filtrarlos con if.

Clase 43 • Módulo 3: Creación, Ejecución y Reversión
</> 4Geeks academy

🔄 Módulo 3: Creación, Ejecución y Reversión de Migraciones (`2.2`, `2.3`)

Autogenerate • Upgrade Head • Downgrade -1
📌 Ciclo de Vida de una Revisión:

• Autogeneración: alembic revision --autogenerate -m "msg" detecta cambios y crea las funciones upgrade() y downgrade().
• Aplicación: alembic upgrade head ejecuta los cambios pendientes.
• Rollback: alembic downgrade -1 deshace la última migración.

⏪ Explicación Feynman:

Cada migración tiene un botón de "Adelantar" (upgrade) y uno de "Rebobinar" (downgrade). Si instalas un mueble nuevo y no cabe en la sala, presionas rebobinar y el sistema desatornilla ese mueble exacto dejando la sala como estaba.

alembic/versions/a1b2c3_add_duration.py
Python & CLI
def upgrade():
    op.add_column('songs', sa.Column('duration_seconds', sa.Integer(), nullable=True))

def downgrade():
    op.drop_column('songs', 'duration_seconds')

# Comando para aplicar en terminal:
$ uv run alembic upgrade head

🌐 Consumo de APIs & Capa de Abstracción HTTP

API Client • Bearer Token • Error Handling
📌 Patrón API Service / Client:

Encapsular todas las llamadas HTTP dentro de un cliente centralizado (ej. lib/inventory.ts). Evita desparramar llamadas fetch crudas en useEffect o componentes.

🔑 Tokens Bearer & Errores (4xx/5xx):

Inyecta automáticamente Authorization: Bearer <token>. Si !response.ok, parsea el campo detail de FastAPI y propaga un mensaje amigable para la UI.

lib/inventory.ts
TypeScript
export async function fetchInventory(token: string) {
  const res = await fetch("/api/v1/inventory", {
    headers: {
      "Authorization": `Bearer ${token}`,
      "Content-Type": "application/json"
    }
  });
  if (!res.ok) {
    const err = await res.json();
    throw new Error(err.detail || "Error HTTP");
  }
  return res.json();
}

engine = create_engine(DATABASE_URL, pool_pre_ping=True) # Conexión SQL

def get_db():
    with Session(engine) as session:
        yield session # Sesión controlada por request

📊 Módulo 3: Inmutabilidad de Stock y Registro Contable (Ledger Pattern)

Ledger Pattern • Inbound vs Outbound • Double Entry
📌 Principio Contable (No UPDATE directo):

El stock nunca se edita directamente (UPDATE products SET stock = X está prohibido).
$$\text{Stock Actual} = \sum(\text{Inbound}) - \sum(\text{Outbound})$$ Todo movimiento es un registro histórico inmutable asociado al user_uuid.

🐖 Explicación Feynman:

La alcancía del banco. No hay perilla mágica para cambiar el saldo. Para tener más dinero metes monedas (Inbound). Para usar dinero anotas el retiro (Outbound). El total es la cuenta real de entradas menos salidas.

🛑 Módulo 4: Prevención de Stock Negativo y Errores de Negocio (HTTP 400)

HTTP 400 Bad Request • Stock Check • Transaction Safety
📌 Concepto:

Validación previa transaccional. Antes de guardar una orden Outbound, el sistema calcula el stock disponible. Si salida > disponible, frena la transacción con HTTP 400 Bad Request e impide saldos negativos.

🍪 Explicación Feynman:

Tienes una caja con 3 galletas. Si te piden 5, no puedes quedar con "menos 2 galletas". Cuentas antes de entregar: si no alcanzan, respondes "No las puedo dar, solo quedan 3" (HTTP 400) y dejas la caja intacta.

@router.post("/orders/outbound")
def create_outbound(data: OutboundCreate, db: Session = Depends(get_db)):

    if data.quantity > stock:
        raise HTTPException(

            detail=f"Stock insuficiente. Disponible: {stock}"
        )
    order = StockExit(**data.dict())
    db.add(order)

import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function middleware(req: NextRequest) {
  const token = req.cookies.get("auth_token")?.value;
  if (!token && req.nextUrl.pathname.startsWith("/backoffice")) {
    return NextResponse.redirect(new URL("/login", req.url));
  }
}

📌 Propósito & Misión del Backend:

Construir el servicio central de API REST encargado de persistir modelos relacionales, gestionar sesiones get_db, conectar TinyDB con PostgreSQL/Supabase, aplicar migraciones Alembic y hacer cumplir las reglas contables de inventario inmutable (Ledger Pattern).

⚙️ Explicación Feynman:

Es la bóveda y el libro contable de la empresa. Nadie entra a cambiar los números a mano: la API recibe peticiones HTTP, verifica credenciales en TinyDB y anota las entradas y salidas de mercancía en PostgreSQL de forma atómica y segura.

📋 Checklist de Entregables Clave (Proyecto 1):
  • 1. Dual DB Setup (database.py): Integración NoSQL (TinyDB) + SQL Engine con Depends(get_db).
  • 2. Modelos ORM (models.py): Tabla StockEntry, StockExit, Product con user_uuid plano.
  • 3. Ledger Inmutable: Cálculo dinámico Stock = sum(Inbound) - sum(Outbound).
  • 4. Prevención Stock Negativo: Error HTTP 400 Bad Request si salida > disponible.
  • 5. Migraciones Alembic: Control de versiones DDL con alembic upgrade head.

🔄 Diferencia & Arquitectura Integrada entre Ambos Proyectos

Client-Server Pattern • Decoupled Architecture • Fullstack Contract
3 </> Project 1 (Backend API)
  • Capa: Servidor de Negocio & Persistencia (FastAPI).
  • Responsabilidad: Valida schemas Pydantic, administra transacciones ORM, conecta PostgreSQL/TinyDB y frena stock negativo (HTTP 400).
  • Seguridad: Verifica y genera JWT Bearer Tokens.
  • Entregable: API REST documentada en Swagger (/docs).
4 </> Project 2 (Backoffice UI)
  • Capa: Cliente Frontend de Administración (Next.js / React).
  • Responsabilidad: Renderiza UI/UX, captura formularios reactivos, almacena JWT en Cookies/State y consume la API vía lib/inventory.ts.
  • Seguridad: Middleware de protección de rutas (/backoffice).
  • Entregable: Dashboard interactivo de gestión de bodega.
🔗 Flujo de Integración Cliente-Servidor (End-to-End):
[Backoffice Client (Next.js)] ──(HTTP fetch + Bearer Token)──> [Backend API (FastAPI)] ──(SQLModel ORM)──> [PostgreSQL / Supabase DB]
