🗄️ Fundamentos de Bases de Datos Relacionales & SQL

Integridad ACID • DDL vs DML
📌 ¿Por qué SQL y Bases Relacionales?

Las bases de datos relacionales organizan la información en tablas compuestas por filas (registros) y columnas (atributos). SQL (Structured Query Language) es el estándar industrial para definir, consultar y auditar datos con consistencia atómica.

🛠️ DDL (Data Definition Language)

Define la estructura de la base de datos: CREATE TABLE, ALTER TABLE, DROP TABLE. Establece tipos de datos, llaves primarias y restricciones.

🔍 DML (Data Manipulation Language)

Manipula y consulta los datos almacenados: SELECT, INSERT, UPDATE, DELETE. Permite filtrar y calcular métricas de auditoría.

💻 Creación de Tablas & Inserción en SQL

schema.sql
SQL
-- 1. DDL: Estructura de la Tabla
CREATE TABLE students (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(120) UNIQUE NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 2. DML: Inserción y Consulta
INSERT INTO students (name, email)
VALUES ('Juan Pérez', 'juan@example.com');

SELECT id, name, email FROM students;
🥇 Primary Key (PK):

SERIAL PRIMARY KEY asigna un entero autoincremental único por cada fila, garantizando la identidad inmutable del registro.

🛡️ Constraints `NOT NULL` & `UNIQUE`:

La BD valida automáticamente a la entrada que el nombre no esté vacío y que el correo no se repita en la tabla.

🔑 Primary Keys (PK) & Restricciones de Integridad

Identificador Único • Reglas de Motor
📌 Explicación Técnica:

La Primary Key es una columna que identifica de manera única e inconfundible cada fila en una tabla. Las restricciones (Constraints) como NOT NULL, UNIQUE y CHECK fuerzan la integridad de los datos directamente en el motor relacional.

💳 Ejemplo Feynman (para 5 años):

Imagina el número de DNI o Cédula en el Registro Civil. No pueden existir dos personas vivas con el mismo número de DNI, y tampoco puedes registrar a un bebé sin asignarle un número. La Primary Key es ese DNI que jamás cambia en tu vida.

📁 Archivos donde interviene / se configura:

En scripts DDL (db/schema.sql), archivos de migración inicial y definiciones de modelos ORM.

📜 Audit Trail & Registro Histórico de Cambios

Trazabilidad • Tablas de Auditoría
📌 Explicación Técnica:

Un Audit Trail en SQL consiste en almacenar en una tabla dedicada (audit_logs) cada modificación o inserción realizada en el sistema. Permite saber quién modificó qué dato, en qué fecha exacta (`timestamp`) y el estado previo/nuevo.

✈️ Ejemplo Feynman (para 5 años):

Es la caja negra de un avión o la libreta del portero del edificio: cada persona que entra o sale deja anotada su hora exacta y su nombre. Si algo se rompe o desaparece, no hay adivinanzas: abres la caja negra y ves exactamente qué pasó.

💻 Consulta SQL de Auditoría Típica: 
SELECT u.email, a.action, a.timestamp 
FROM audit_logs a JOIN users u ON a.user_id = u.id 
ORDER BY a.timestamp DESC;
