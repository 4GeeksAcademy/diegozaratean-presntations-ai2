⚡ Latencia, Throughput y Percepción del Usuario

Performance Audit • Web Vitals
📌 Concepto Fundamental:

La optimización de arquitectura abarca dos mundos interconectados: el Backend (tiempo de respuesta del servidor, costo de serialización y accesos a la BD) y el Frontend (métricas Core Web Vitals, velocidad de renderizado y fluidez de interacción).

⚙️ Performance Backend

Mide la latencia de respuesta (TTFB - Time to First Byte) y el consumo de CPU/Memoria al procesar y convertir objetos de base de datos a cadenas JSON.

🎨 Core Web Vitals (Frontend)

Mapea la experiencia real del usuario: qué tan rápido se muestra el contenido principal (LCP), la estabilidad visual (CLS) y la velocidad de respuesta táctil (INP).

💡 Analogía Feynman: El Restaurante Gourmet

El chef puede preparar la comida en 2 minutos (Backend rápido), pero si el mesero tarda 10 minutos en empacar el plato en 5 cajas concéntricas (Serialización pesada) o el plato es tan pesado que rompe la mesa al servirlo (Frontend inestable CLS), la experiencia del comensal será arruinada.

📦 ¿Qué es la Serialización y Por Qué consume CPU?

📌 El Ciclo de Transformación de Datos:

La base de datos retorna filas de tabla -> SQLAlchemy las convierte en objetos Python -> Pydantic valida y proyecta los campos -> El encoder convierte los objetos a texto `JSON` en bytes. En respuestas grandes (ej. 5,000 registros), ¡el 70% del tiempo de CPU se gasta en la serialización JSON!

🐢 Serializador Estándar Python (`json`)

Escrito puramente en Python. Lento al formatear tipos complejos como datetime, UUID o decimales. Genera cuellos de botella severos.

🚀 Serializadores Ultra-Rápidos (`orjson` / Pydantic v2)

Escritos en Rust/C. `orjson` es hasta 10 veces más rápido serializando objetos y maneja bytes de forma nativa sin copias adicionales en memoria.

✂️ Proyección de Campos DTO: Menos Payload, Más Velocidad

# ❌ Over-fetching (Payload gigante)
@app.get("/items")
def get_items(db: Session = Depends(get_db)):
  # Devuelve todas las columnas y relaciones de BD
  return db.query(ItemModel).all()
# ✅ Proyección DTO Optimizada
class ItemSummaryDTO(BaseModel):
  id: int
  name: str
  price: float

@app.get("/items", response_model=list[ItemSummaryDTO])
def get_items(db: Session = Depends(get_db)):
  return db.query(ItemModel.id, ItemModel.name, ItemModel.price).all()
💡 Reducción de Red:

Filtrar los campos necesarios en la consulta SQL reduce el tamaño de la respuesta JSON de 4.5 MB a 180 KB, disminuyendo el tiempo de transferencia en redes móviles drásticamente.

1. Compresión de Imágenes (WebP / AVIF)

Clase 45 • Antipatrones Graves de Rendimiento
</> 4Geeks academy

⚠️ Los 3 Antipatrones Que Destruyen la Velocidad Web

1. Bloqueo de la Línea Principal (Main Thread Blocking)

Ejecutar cálculos pesados o bucles de CPU síncronos en el hilo de FastAPI congela el servidor para todas las demás peticiones concurrentes.

2. Fuga de Datos por Falta de Paginación

Retornar 50,000 filas de base de datos en un solo endpoint sin limit ni offset provocará errores Out-Of-Memory (OOM).

3. Imágenes Sin Dimensiones Reservadas (CLS Chaos)

Cargar imágenes sin especificar width y height explícitos hace que la página brinque bruscamente al cargar, arruinando el CLS.
